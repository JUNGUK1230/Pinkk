# PINKK 스마트 주차 시스템

## 1. 프로젝트 개요

### 상단 카메라와 LiDAR 기반 다중 차량 스마트 주차 시스템

- 상단 카메라로 주차장 전체와 차량 위치 확인
- 차량별 LiDAR를 이용해 두 차량의 신원 구분
- 빈 주차면과 운행 단계에 따라 목표 위치 배정
- 검증된 경로와 MPC를 이용한 입차·주차·출차
- 관리자·사용자 웹을 통한 상태 확인과 요청 처리

핵심 규모

- 운영 차량 2대
- 일반 주차면 8면, 충전면 2면
- 검증된 고정 경로 32개
- 약 2.5×2.2m 규모의 실내 주차장

추천 이미지: [전체 주차장 BEV](/home/junguk/PINKK/src/central_control/camera_tools/first_map/camera_bev.png)

## 2. 전체 시스템 구성

### 인식부터 차량 제어까지 하나의 시스템으로 통합

상단 카메라 관측  
→ 차량 검출 및 주차면 점유 판정  
→ LiDAR와 카메라 위치 비교를 통한 차량 식별  
→ 목표 주차면 및 경로 선택  
→ 카메라·바퀴 주행 정보·LiDAR 위치 융합  
→ MPC 경로 추종  
→ 웹 상태 표시 및 긴급정지

역할 분리

- 중앙 관제: 인식, 차량 식별, 공간 배정, 경로 선택
- 차량 제어: 위치 융합, 경로 추종, 안전정지
- 웹: 입차·출차 요청, 차량 상태, 배터리, 긴급정지

## 3. 차량 검출 및 다중 차량 식별

### 상단 영상과 차량별 LiDAR를 결합한 차량 ID 확인

- 상단 영상을 Bird’s-Eye View로 변환
- YOLO Segmentation으로 차량 형상 검출
- ByteTrack으로 프레임 간 차량 추적
- 차량 형상과 주차면이 겹치는 비율로 점유 여부 판정
- 카메라에서 검출한 차량의 중심 위치와 방향 계산

다중 차량 식별 과정

1. 차량 1과 차량 2의 LiDAR 데이터는 각각 구분된 통신 영역으로 수신
2. 각 LiDAR 데이터를 지도에 정합해 차량별 위치 후보 계산
3. LiDAR 위치와 카메라에서 검출한 차량 위치 비교
4. 위치가 가장 잘 일치하는 카메라 차량과 실제 차량 ID 연결
5. 연결이 확정된 차량의 통신 영역으로 위치와 경로 전달

안전 조건

- 가장 좋은 조합과 두 번째 조합의 차이가 충분한지 확인
- 같은 연결 결과가 두 번 연속 확인돼야 차량 ID 확정
- 위치 일치도가 낮거나 데이터가 오래되면 차량을 움직이지 않음

## 4. 고정 경로 생성 방식

### 실측 좌표와 차량 기구학을 반영한 사전 검증 경로

현재 고정 경로는 Hybrid A* 결과를 그대로 저장한 것이 아니다.

생성 과정

1. 실제 주차장의 출발점, 주차면, 충전면, 출구 좌표 측정
2. 측정 좌표를 기준으로 공통 도로 중심선 설정
3. 직선과 접선 원호를 이용해 공통 도로 생성
4. 특수 합류 구간은 Bezier와 Reeds–Shepp 경로로 연결
5. 각 주차면에 전진 접근과 후진 주차 동작 추가
6. 출발지·공통 도로·목표 주차면 경로를 하나로 결합
7. 차량 크기와 회전반경을 적용해 충돌과 곡률 검사
8. 검증된 경로를 0.5cm 간격으로 저장

주차 경로 특징

- 상단 일반 주차면: 최소 14cm 회전반경의 연속 후진 진입
- 하단 일반 주차면: 최소 20cm 회전반경의 연속 후진 진입
- 충전면: 후진, 전진 정렬, 직선 후진으로 구성된 3-point 진입
- 방향 전환 지점에서는 완전히 정지한 후 다음 구간 진행

운영 방식

- 입차·충전·재주차·출차를 포함한 32개 경로 사전 생성
- 운영 중에는 경로를 다시 탐색하지 않고 현재 위치와 목표에 맞는 경로 선택
- 동일한 요청에 동일한 경로를 사용해 실차 동작의 재현성 확보

## 5. 위치 융합 및 MPC 차량 제어

### 센서의 장점을 결합한 차량 위치 추정

- 상단 카메라: 지도상의 절대 위치 제공
- 바퀴 회전 기반 주행 정보: 카메라 프레임 사이의 빠른 상대 이동 제공
- LiDAR 지도 정합: 출발 시 차량의 절대 방향 보정
- 카메라 처리 지연 동안 이동한 거리는 바퀴 주행 정보로 보상
- 주행 시작 후에는 갑작스러운 방향 보정을 제한해 경로 추종 안정화

### 전진·후진 경로를 위한 MPC

- 차량 위치와 방향 오차를 예측해 속도와 회전량 계산
- 전진과 후진 구간을 구분해 경로 추종
- 방향 전환점에서 정지한 뒤 다음 구간으로 전환
- 차량 속도, 회전 속도, 가속도, 휠 속도 제한 반영
- 같은 경로가 다시 전달돼도 기존 진행 위치 유지

안전정지 조건

- 위치, 경로 또는 LiDAR 데이터 수신 중단
- 진행 방향 장애물 감지
- 유효하지 않은 경로
- MPC 계산 실패
- 차량 방향 오차 과다
- 중복된 속도 명령 감지

## 6. Nav2를 사용하지 않은 이유

### 핵심 기능을 Nav2에 연결하려면 대부분 별도 개발이 필요

- 상단 카메라 기반 위치를 Nav2 구조로 변환하는 연결 계층 필요
- 경로점별 전진·후진 정보와 방향 전환 정지를 처리하는 별도 기능 필요
- 현재 MPC를 사용하기 위한 전용 제어 모듈 필요
- 차량 크기, 중심 위치, 휠 속도와 곡률 제한을 다시 반영해야 함
- 두 차량 식별과 주차·충전 배정은 Nav2 밖에서 별도 구현 필요

현재 환경에서 직접 구현이 적합했던 이유

- 주차장 구조와 모든 출발·목표 위치가 고정
- 범용 재탐색보다 32개 경로의 반복 재현이 중요
- 0.5cm 간격으로 경로별 충돌 여부 사전 검증
- 차량 ID나 위치가 불확실하면 자동 복구보다 정지가 안전
- 경로 생성기와 MPC가 동일한 차량 모델과 전후진 정보를 공유

선택의 한계

- 동적 장애물 온라인 우회 미지원
- 범용 복구 동작과 동적 지도 기능 부족
- 주차장 구조가 변경되면 경로를 다시 생성하고 검증해야 함

결론

> 고정된 소형 주차장에서는 Nav2 통합 비용보다 검증된 경로의 결정성과
> cm 단위 제어가 더 중요해 경로 생성기부터 MPC까지 직접 구성했다.

## 7. 웹 관제 및 시스템 안전

### 관리자 웹

- 주차장 영상과 차량 상태 확인
- 차량별 배터리 확인
- 입차·충전·출차 요청
- 차량별 긴급정지 및 해제

### 사용자 웹

- 입차 및 출차 요청
- 배터리 상태 확인
- 주차장 실시간 영상 확인

### 통합 안전 구조

- 차량별 통신 영역을 분리해 명령 혼선 방지
- 웹은 차량을 직접 조종하지 않고 운행 요청만 전달
- 실제 속도 명령은 차량별 MPC에서만 생성
- 출차 요청은 자동 주차·충전 배정보다 우선
- 긴급정지는 명시적으로 해제하기 전까지 유지

## 9. 현재 한계와 향후 계획

### 현재 한계

- 자동 차량 식별 로직은 구현됐지만 현재 실차 시험은 수동 연결을 기본으로 사용
- MPC 전진 재합류 시험에서 중심선을 약 6.2mm 초과하는 한 항목 존재
- 동적 장애물은 우회하지 않고 정지로 처리
- 고정 지도이므로 주차장 구조 변경 시 경로 재생성 필요
- 사용자 웹은 내부망 시험용 서버로 운영

### 향후 계획

1. MPC 전진 재합류 오차 보정
2. 자동 차량 식별 반복 시험과 기본 모드 전환
3. 반복 입차·주차·출차 시험을 통한 성공률 측정
4. 동적 장애물 우회 기능 추가
5. 지도와 카메라 변경 시 보정 절차 자동화

## 10. 결론

### 프로젝트 성과

- 인식, 차량 식별, 경로 계획, 제어, 웹 관제를 하나의 시스템으로 통합
- 두 차량을 구분해 각 차량에 독립적인 위치와 경로 전달
- 실제 주차장과 차량 크기를 반영한 32개 고정 경로 확보
- 전진과 후진이 포함된 정밀 주차 경로를 MPC로 제어
- 센서 및 제어 이상 시 정지하는 안전 구조 적용

### 최종 메시지

> PINKK는 상단 카메라 기반 중앙 관제와 차량별 센서를 결합해 다중 차량의
> 입차·주차·출차를 수행하도록 설계한 스마트 주차 통합 시스템이다.
