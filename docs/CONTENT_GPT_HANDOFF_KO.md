# PINKK 발표 콘텐츠 제작용 상세 인계서

기준일: 2026-08-26  
용도: 다른 콘텐츠 작성 GPT가 PPT 문구, 발표 대본, 보고서 초안을 만들 때 사용하는
사실 기반 입력 자료

## 0. 반드시 지켜야 할 범위

발표 대상은 다음 여섯 영역이다.

1. 상단 카메라 기반 차량 검출과 주차면 점유 판정
2. 차량별 LiDAR와 카메라 위치를 이용한 다중 차량 식별
3. 주차 mission 배정과 고정 경로 생성·선택
4. 카메라·바퀴 주행 정보·LiDAR를 결합한 차량 pose 융합
5. 전진·후진 경로를 추종하는 차동구동 MPC
6. 관리자·사용자 웹과 시스템 안전정지

로봇팔, USB 포트 인식, USB 삽입 제어는 발표 범위에서 제외한다.

## 1. 한 문장 정의

PINKK는 상단 카메라로 주차장 전체와 여러 차량을 관측하고, 차량별 LiDAR로
각 차량의 신원을 구분한 뒤, 사전 검증 경로와 MPC를 이용해 두 대의 차량을
입차·주차·출차시키는 ROS 2 기반 스마트 주차 시스템이다.

현재 manifest와 회귀 검사는 32개를 기준으로 한다.

## 3. 프로젝트가 해결하려는 문제

### 3.1 전체 공간 인식

차량 자체 센서만으로는 주차장 전체의 빈자리와 다른 차량을 동시에 보기 어렵다.
상단 카메라 한 대를 이용해 전체 주차장을 관측하고 주차면 점유 상태를 중앙에서
판단한다.

### 3.2 두 차량의 신원 구분

카메라 추적기의 track ID는 일시적이다. 차량이 가려지거나 다시 나타나면 ID가
바뀔 수 있으므로 실제 차량 1·2의 영속 ID로 바로 사용할 수 없다. 반면 LiDAR
데이터는 차량별 통신 영역으로 수신되므로 어느 차량의 데이터인지 알고 있다.
LiDAR의 지도상 위치와 카메라 차량 위치를 비교해 실제 차량과 camera track을
연결한다.

### 3.3 좁은 공간의 전진·후진 주차

차량 크기에 비해 주차 공간이 좁고 경로에 전진과 후진이 함께 포함된다. 위치
경로만 제공해서는 방향 전환 시점을 안정적으로 처리하기 어렵다. 각 경로점에
전진·후진 정보를 명시하고 방향 전환점에서 완전히 정지하도록 구성한다.

### 3.4 불확실한 상황의 안전

카메라, LiDAR, 경로 또는 통신이 불확실할 때 임의로 계속 주행하지 않는다.
유효한 최신 입력이 없으면 정지하는 fail-closed 정책을 사용한다.

## 4. 전체 시스템 흐름

1. 상단 USB 카메라 영상을 보정한다.
2. Homography를 이용해 1600×800 Bird’s-Eye View를 만든다.
3. YOLO Segmentation으로 차량 mask를 검출한다.
4. ByteTrack으로 프레임 간 camera track을 유지한다.
5. 차량 mask로 차량 중심·방향과 주차면 점유 상태를 계산한다.
6. 차량별 LiDAR scan을 공용 LiDAR map에 정합한다.
7. LiDAR 위치와 camera track 위치를 비교해 실제 차량 ID를 연결한다.
8. 현재 주차 위치와 운행 단계에 따라 목표를 배정한다.
9. 32개 검증 경로 중 현재 위치와 목표에 해당하는 경로를 선택한다.
10. 카메라 위치, 바퀴 주행 정보, LiDAR 방향 정보를 융합한다.
11. MPC가 융합 pose와 경로를 이용해 차량 속도와 회전량을 계산한다.
12. 관리자·사용자 웹에 영상, 상태, 배터리와 운행 상태를 표시한다.

## 5. 영상 인식과 좌표 변환

### 5.1 Camera BEV

- 카메라 내부 파라미터와 왜곡 계수로 원본 영상을 보정한다.
- Homography를 적용해 위에서 내려다본 1600×800 Camera BEV로 변환한다.
- Camera BEV와 LiDAR map은 별도의 registration으로 연결한다.
- 카메라 화면과 LiDAR map은 회전과 위치가 다르므로 단순 pixel 복사가 아니다.
- 최종 위치는 차량 중심, m 단위, 공통 `lidar_map` frame으로 통일한다.

### 5.2 차량 검출과 추적

- YOLO segmentation mask를 사용한다.
- 단순 bounding box보다 mask가 차량 장축 방향과 주차면 겹침 판정에 적합하다.
- ByteTrack이 화면 안의 임시 track ID를 유지한다.
- 차량 중심과 yaw에는 지수 저역통과 필터를 적용한다.
- 큰 위치 점프와 오래된 track은 거부한다.

### 5.3 주차면 점유 판정

- 각 주차면은 고정 polygon으로 정의돼 있다.
- 차량 mask와 주차면 polygon의 겹침 비율이 기준 이상이면 점유로 판정한다.
- 공간 점유 후보와 실제 제어 대상 차량은 서로 다른 confidence 기준을 사용한다.
- 낮은 confidence 차량 때문에 빈자리를 잘못 배정하는 문제를 줄이기 위한 분리다.

## 6. Namespace 기반 다중 차량 식별

### 6.1 핵심 개념

차량 1과 차량 2의 LiDAR scan은 처음부터 서로 다른 namespace에서 수신된다.
따라서 각 scan의 실제 차량 ID는 이미 알고 있다. 모르는 것은 카메라의 임시
track이 실제 어느 차량인지다.

예시:

- 차량 1 LiDAR를 지도에 정합한 위치가 camera track 7의 위치와 일치
- 차량 2 LiDAR를 지도에 정합한 위치가 camera track 12의 위치와 일치
- vehicle 1과 track 7을 연결
- vehicle 2와 track 12를 연결
- track 7에서 계산한 카메라 위치와 선택 경로는 차량 1 namespace로 전달
- track 12에서 계산한 카메라 위치와 선택 경로는 차량 2 namespace로 전달

### 6.2 실제 매칭 절차

1. 차량별 최신 LaserScan을 차량 좌표계의 점군으로 변환한다.
2. camera track의 중심 위치 주변에서 LiDAR x/y/yaw를 지도에 정합한다.
3. 탐색 범위는 camera 위치 주변 ±25cm다.
4. 차량과 track의 모든 가능한 일대일 조합을 만든다.
5. 각 조합에서 scan endpoint와 지도 장애물 사이의 평균 오차를 계산한다.
6. 전체 비용이 가장 낮은 일대일 조합을 선택한다.
7. 최대 정합 오차, 1·2순위 비용 차이, 연속 확인 조건을 검사한다.
8. 조건을 통과한 경우에만 vehicle ID와 camera track 연결을 확정한다.

### 6.3 현재 기준값

- LiDAR-camera 매칭 주기: 0.75초
- LiDAR scan timeout: 1.5초
- 카메라 위치 주변 탐색: ±25cm
- 허용하는 최대 지도 정합 오차: 8cm
- 1·2순위 조합에 필요한 최소 비용 차이: 1cm
- 같은 매칭 결과의 연속 확인: 2회

### 6.4 중요한 해석

- LiDAR x/y는 주로 camera track의 차량 ID를 확인하는 데 사용한다.
- 실제 MPC 위치는 카메라 x/y와 LiDAR·바퀴 주행 정보의 yaw 융합 결과다.
- 자동 연결이 확정되기 전에는 잘못된 차량이 움직이지 않도록 pose와 경로를
  발행하지 않는다.
- 자동 식별 로직은 구현돼 있으나 2026-08-26 실차 동작 시험 기본값은 수동
  차량 연결 모드다.
- 수동 모드는 화면의 camera track을 운영자가 차량 1 또는 차량 2에 연결한다.

## 7. Mission과 경로 배정

### 7.1 운행 단계

기본 운행 흐름은 다음과 같다.

- START에서 일반 주차면 P5~P8 또는 충전면 C1~C2로 이동
- P5~P8에서 충전면 C1~C2 또는 EXIT로 이동
- C1~C2에서 일반 주차면 P1~P4 또는 EXIT로 이동
- P1~P4에서 EXIT로 이동

동일 단계 내부 이동은 허용하지 않는다. 예를 들어 P8에서 P7, C1에서 C2,
P1에서 P2로 직접 이동하는 경로는 운영 대상이 아니다.

### 7.2 현재 위치 판정과 경로 선택

- 카메라로 검출한 차량 중심이 START 또는 어느 endpoint 안에 있는지 판정한다.
- 현재 section과 목표 section에 해당하는 고정 경로 전체를 선택한다.
- 차량이 도로 중간인 TRANSIT 상태에서는 현재 위치부터 경로를 새로 자르지 않는다.
- 운행 중 재계획 요청은 차량별로 보관한 마지막 전체 trajectory를 재발행한다.
- 출차 요청은 자동 주차·충전 배정보다 우선한다.
- 경로는 선택 즉시 발행하고 기본 1초 주기로 다시 발행한다.
- 목표 변경이나 경로 무효화 시 이전 경로 재발행을 중단한다.

## 8. 현재 고정 경로의 생성 방식

### 8.1 반드시 지켜야 할 설명

현재 32개 고정 경로는 Hybrid A* 결과를 그대로 저장한 것이 아니다. 실제
주차장에서 측정한 기준 좌표를 바탕으로 직선, 접선 원호, Bezier,
방향 제한 Reeds–Shepp와 주차면별 maneuver를 조합해 만든 기하학적 경로다.

Hybrid A* 계열은 초기 경로 실험과 오프라인 진단용으로 남아 있으며 현재
실시간 운영 경로를 매번 탐색하지 않는다.

### 8.2 생성 입력

고정 경로 설정에는 다음 값이 들어 있다.

- START와 EXIT의 기준 pose
- P1~P8, C1~C2의 도로 staging pose
- 각 주차면 내부 최종 goal pose
- 공통 도로의 road backbone 기준점
- 구간별 회전반경
- 주차 진입 시작점과 정렬 pose
- 허용되는 source→target 전이

모든 좌표는 `lidar_map_cm` 기준이다.

### 8.3 공통 도로 생성

1. road backbone 기준점을 mission 진행 순서대로 배치한다.
2. 기준점 사이는 직선으로 연결한다.
3. 각진 모서리는 앞뒤 직선에 접하는 원호로 교체한다.
4. 공통 도로의 기본 회전반경은 16cm다.
5. 넓은 상단 코너에는 18cm 회전반경을 사용한다.
6. 전체 centerline을 0.5cm 간격으로 샘플링한다.
7. 각 pose에서 회전된 12×10cm 차량 footprint가 지도와 충돌하는지 검사한다.

### 8.4 주차면 connector와 maneuver

공통 도로와 주차면 goal 사이에는 endpoint별 전용 경로를 붙인다.

- 출차: 주차 goal에서 공통 도로 attachment까지 전진 Reeds–Shepp connector
- P5~P8 진입: 전진 접근 후 최소 14cm 반경의 단일 연속 후진
- P1~P4 진입: 전진 접근 후 최소 20cm 반경의 단일 연속 후진
- C1·C2 진입: 큰 반경의 초기 후진, 짧은 전진 정렬, 44cm 직선 후진
- C1·C2 정렬 과정은 후진→전진→후진의 3-point 형태
- goal yaw는 주차면에 들어가기 전에 맞추고 마지막 구간은 직선 후진

Reeds–Shepp은 전체 지도를 탐색하는 용도가 아니라 두 pose 사이에서 전진 또는
후진 조건을 만족하는 짧은 connector 후보를 만드는 데 사용한다. 후보는 차량
footprint 충돌 검사를 통과해야 한다.

### 8.5 특수 연결 구간

- C1에서 하단 주차열로 합류하는 구간은 5차 Bezier를 사용한다.
- Bezier는 시작과 끝에서 곡률이 0이 되도록 구성한다.
- C2에서 하단 주차열로 합류하는 구간은 전진만 허용한 Reeds–Shepp 연결이다.
- START에서 C1로 가는 구간은 Camera BEV의 직선 방향을 따르는 전용 waypoint를
  사용한다.
- 이후 목표까지는 공통 centerline의 필요한 부분을 이어 붙인다.

### 8.6 한 mission 경로의 조립

각 경로는 다음 세 부분을 결합한다.

1. 출발지가 주차면이면 goal에서 도로로 나오는 전진 exit connector
2. source와 target 사이의 공통 도로 또는 특수 연결 구간
3. 도로에서 target goal로 들어가는 entry connector와 후진 maneuver

예시:

- START→C1: START 전용 도로 + C1 접근 + C1 3-point 진입
- C1→P3: C1 전진 출차 + C1→P1 Bezier + P1→P3 공통 도로 + P3 후진 주차
- P6→EXIT: P6 전진 출차 + P6→EXIT 공통 도로

### 8.7 검증과 출력

각 경로는 다음을 검사한다.

- 회전된 차량 footprint와 지도 장애물의 충돌
- 최소 회전반경을 위반하는 곡률
- 마지막 직선 후진 구간의 yaw 변화
- 정렬 중 차량 후미가 목표 주차면에 너무 일찍 진입하는지
- 허용되지 않은 mission 전이인지

생성과 충돌 검사는 rear axle pose 기준이다. 검증 후 pose를 진행 방향으로 4cm
옮겨 차량 중심 경로로 변환한다. 제어용 경로는 0.5cm 간격이며 각 점에는 위치,
yaw, 전진·후진 direction이 들어 있다.

운영 중에는 경로 생성기를 실행하지 않는다. 이미 저장된 32개 경로 중 현재
section과 목표에 맞는 하나를 선택해 차량에 전달한다.

## 9. 위치와 방향 융합

### 9.1 입력 신호의 역할

| 입력 | 역할 |
|---|---|
| 상단 카메라 | 절대 x/y 위치 |
| 바퀴 odometry | 카메라 프레임 사이의 상대 이동과 상대 yaw |
| LiDAR map matching | 출발 전 절대 yaw 초기화와 제한적 drift 보정 |
| 고정 경로의 첫 yaw | 출발 시 map 방향 prior |
| 실제 속도 명령 방향 | 전진·후진 이동 heading 판단 |

### 9.2 융합 핵심

- 카메라 x/y는 절대 위치지만 처리 지연이 있다.
- 카메라 촬영 이후 차량이 이동한 양을 odometry로 보상한다.
- odometry는 빠르지만 누적 오차가 생기므로 절대 위치로 단독 사용하지 않는다.
- LiDAR heading은 출발 전 방향을 맞추는 데 사용한다.
- 경로 시작 후 LiDAR heading correction이 갑자기 방향을 바꾸지 않도록 잠근다.
- pose, odometry 또는 scan이 timeout되거나 정합 품질이 나쁘면 pose를 발행하지
  않는다.

## 10. MPC 차량 제어

### 10.1 제어 모델

- 차동구동 차량의 rear-axle 운동학을 사용한다.
- 제어 기준점은 차량 중심 offset을 반영한다.
- 예측 horizon의 signed speed와 curvature를 최적화한다.
- 수치 최적화에는 SciPy SLSQP를 사용한다.

### 10.2 최적화 항목

- 경로 위치 오차
- 차량 yaw 오차
- 목표 속도 오차
- 경로 곡률 오차
- 속도 변화량
- 곡률 변화량

### 10.3 물리 제한

- 좌우 휠 속도
- 선속도와 각속도
- 가속도
- 곡률
- 곡률 변화량

### 10.4 전진·후진 처리

- direction이 1이면 전진, -1이면 후진이다.
- MPC는 현재 gear block 안에서만 최근접 경로점을 찾는다.
- 다른 direction 구간의 가까운 점을 잘못 선택하지 않는다.
- cusp에 도달하면 정지한 뒤 다음 gear block으로 전환한다.
- 같은 경로가 반복 발행되면 progress와 warm start를 유지한다.

## 11. 안전정지

다음 조건 중 하나라도 발생하면 0속도를 발행한다.

- pose timeout
- path timeout 또는 path invalid
- LaserScan timeout
- 진행 방향 장애물
- 유효하지 않은 trajectory
- MPC solver 실패
- 큰 heading 오차
- 예상하지 않은 추가 속도 명령 publisher
- 웹 긴급정지 latch 활성화

현재 동적 장애물은 온라인으로 우회하지 않는다. 진행 방향 LiDAR sector에서
장애물을 감지하면 정지한다.

## 13. Nav2를 사용하지 않은 설계 근거

### 13.1 핵심 결론

Nav2를 적용해도 PINKK에 필요한 핵심 부분은 대부분 custom adapter와 plugin으로
다시 만들어야 했다. 고정된 초소형 주차장에서는 추가 통합 계층보다 32개 경로의
결정성과 cm 단위 검증이 더 중요했다.

### 13.2 Nav2 적용 시에도 필요한 별도 개발

- 외부 상단 카메라 pose를 Nav2 TF·odometry 구조로 변환하는 adapter
- 명시적인 전진·후진 direction을 보존하는 경로 변환 또는 planner plugin
- cusp 완전 정지와 gear block을 처리하는 controller plugin
- 현재 MPC를 Nav2 controller로 연결하는 plugin
- 12×10cm 차량의 중심 offset, 휠 속도와 곡률 제한 재반영
- 차량 ID 연결, 빈 주차면·충전면 배정과 단계 관리를 위한 중앙 coordinator

즉, 핵심 알고리즘은 그대로 직접 만든 뒤 Nav2 lifecycle, action, behavior tree
계층을 추가하는 구조가 된다. 현재 범위에서는 연결 지점과 디버깅 대상이 늘어난다.

### 13.3 직접 구성이 적합했던 이유

- 약 2.48×2.18m의 고정 지도
- 정해진 START, 주차면, 충전면, EXIT
- 32개의 허용 전이만 운영
- 동일 요청에 동일 궤적을 재현하는 것이 중요
- 0.5cm 간격의 경로별 충돌 검사가 중요
- 차량 ID나 외부 pose가 불확실하면 자동 recovery보다 정지가 안전
- 경로 생성기와 MPC가 같은 direction과 차량 모델을 직접 공유

### 13.4 균형 있게 밝혀야 할 한계

Nav2를 사용했다면 동적 costmap, lifecycle, behavior tree, recovery 같은 검증된
기능을 활용할 수 있었다. 현재 직접 구현 구조는 동적 장애물 온라인 우회가 없고
지도 구조가 바뀌면 경로를 다시 생성해야 한다.

향후 주차장이 커지거나 구조가 자주 변하고 동적 우회가 필요해지면, 현재 MPC를
Nav2 controller plugin으로 연결하는 구성이 더 유리할 수 있다.

Nav2와 실제 성능을 비교한 벤치마크 기록은 없다. 따라서 “Nav2보다 성능이
좋아서 선택했다”라고 주장하면 안 된다. 정확한 표현은 “프로젝트 요구 interface와
고정 환경을 기준으로 직접 연결이 더 적합했다”이다.
